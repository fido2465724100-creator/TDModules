# 📜 Регламент и общие правила разработки TDModules (CONTRIBUTING_RULES)

Данный документ является **ОБЯЗАТЕЛЬНЫМ РЕГЛАМЕНТОМ** для любого разработчика и AI-агента, работающего с репозиторием `TDModules` из любых связанных проектов (`Tdroid`, `TDRobotics`, `TDnetScript`, `UniTest`, `Drlmstudio`, `SuperDriver`).

---

## 🔒 Золотые правила работы с TDModules

### Правило 1. «Добавил код — обнови документацию»
Любое изменение в коде (`modules/`) **ОБЯЗАНО** сопровождаться обновлением соответствующего файла в папке `docs/`:
- Добавил метод или класс? Опиши его назначение, сигнатуру, параметры и пример вызова.
- Изменил поведение или исправил баг? Укажи это в описании модуля и в истории изменений.
- Запрещено коммитить код без синхронного обновления документации.

### Правило 2. Семантическое версионирование (SemVer)
Каждое изменение повышает номер релиза в файле `VERSION`:
- **MAJOR (X.0.0)** — ломающие изменения архитектуры или API, несовместимые со старыми проектами.
- **MINOR (1.X.0)** — добавление нового функционала, нового туннеля, нового типа теста без поломки старого кода.
- **PATCH (1.0.X)** — исправление багов, оптимизация, обновление документации.

### Правило 3. «Старый релиз уходит в архив» (Архивирование)
При выпуске нового минорного или мажорного релиза:
1. Текущий срез кода модуля или библиотеки архивируется в папку `releases/vX.Y.Z/`.
2. В файле `CHANGELOG.md` создается запись с точной датой, списком изменений и именем проекта-инициатора (например, `[UniTest]`, `[Tdroid]`).
3. Старые проекты, которые пока не готовы обновиться на новый API, всегда могут продолжить использовать зафиксированную архивную версию из `releases/`.

### Правило 4. Обратная совместимость (Zero-Breakage)
Все модули проектируются с сохранением обратной совместимости:
- Не удаляй старые методы сразу. Пометь их аннотацией `@Deprecated(message = "...", replaceWith = ...)` и оставь работать минимум на один релизный цикл.
- Значения параметров по умолчанию (`default values`) обязательны для всех новых полей в моделях данных, чтобы старые JSON-базы не ломались при десериализации.

### Правило 5. Защита от декомпиляции по умолчанию
Любой новый публичный интерфейс или модуль должен иметь соответствующую секцию правил в `templates/proguard-rules.pro`. Внешние эндпоинты, ключи и токены никогда не пишутся открытым текстом — только через `SecureStringMask` (XOR/AES).

### Правило 6. Стандарт сообщений коммитов (Conventional Commits)
Все коммиты должны следовать международному стандарту `type(scope): description`:
- `feat`: добавление нового функционала или модуля (например, `feat(tdscript): add while loop`).
- `fix`: исправление ошибки или бага (например, `fix(network): resolve heartbeat reconnect timeout`).
- `docs`: изменение или добавление документации (например, `docs: update contributing rules`).
- `test`: добавление или исправление тестов (например, `test(security): add timing attack tests`).
- `refactor`: оптимизация и рефакторинг без изменения внешнего API.
- `chore`: рутинные задачи сборки, версионирования или зависимостей.

### Правило 7. Обязательный шлюз верификации перед коммитом (Pre-commit Testing Gate)
Ни один коммит или релиз не может быть зафиксирован без предварительного успешного выполнения тестов:
- Перед любым `git commit` и пушем разработчик/агент **ОБЯЗАН** выполнить команду `./gradlew test` в корне `TDModules`.
- Если падает хотя бы один тест в любом из модулей — фиксация изменений **СТРОГО ЗАПРЕЩЕНА** до полного устранения проблемы.

## 🤖 Инструкция для AI-агентов других проектов

Если ты AI-агент, открытый в соседней вкладке (`Tdroid`, `TDRobotics`, `TDnetScript` и т.д.):

1. **Перед внесением изменений:**
   - Прочитай `VERSION`, `CHANGELOG.md` и соответствующий файл из `docs/`.
   - Проверь, нет ли уже готового решения твоей задачи.

2. **При добавлении нового функционала:**
   - Внеси код в нужный подкаталог `modules/`.
   - Обнови документ в `docs/`.
   - Подними версию в `VERSION`.
   - Запиши в `CHANGELOG.md` строку:
     ```markdown
     ## [v1.1.0] - ГГГГ-ММ-ДД (Инициатор: НазваниеПроекта)
     - Добавлено: Описание нового функционала
     - Изменено: Что было оптимизировано
     ```
   - Зафиксируй изменения через `git commit`.
